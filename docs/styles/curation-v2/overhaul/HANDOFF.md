## What the cloud agent can and cannot do

- **Can:** audit manifests, rewrite DNA, write briefs and new presets as spec files, apply them, run `styles:*` checks and tests, commit.
- **Cannot:** generate cards. Card generation needs the local Studio server, ChatGPT sign-in and the local SQLite library. Leave `previewStatus: pending` on new presets; the local session generates cards later.
- **Cannot see cards as images** unless the contact sheets are committed or regenerated locally. Card defects already found are in `audits/`. Where no audit exists, audit from text and flag "visual review pending".

## Workflow per category (text side)

1. Pick the next category in pack order (see Progress). List its presets:
   `bun scripts/style-curation/agent-kit.mjs list --pack=<pack>` or read `components/recipes/styles/manifests/packs/<pack>.yaml`.
2. Read every preset manifest in the category. Note template filler, repeated phrases, and fields that do not say _how_ the style is made.
3. Write `specs/<pack>__<slug>.ts` following the two existing specs (the format is the `Spec` type in `tools/apply.ts`):
   - `updates`: new DNA fields for weak presets (keep the preset's identity and name), extra `avoid` rules, and `briefs: [primary, variant01, variant02]`.
   - `creates`: new presets to reach 20. Check for overlap in other packs first (`grep -rhi "^name:" components/recipes/styles/manifests/presets`).
4. Dry-run, then apply:
   `bun docs/styles/curation-v2/overhaul/tools/apply.ts docs/styles/curation-v2/overhaul/specs/<file>.ts --dry`, then without `--dry`.
5. Format and check: `node node_modules/vite-plus/bin/vp fmt <changed yaml/json>`, `bun run styles:validate -- --pack=<pack> --strict-taxonomy`, `bun run styles:runtime`, `bun run styles:dna:audit`, `bun run styles:scene-lock:audit`.
6. Update the category entry in `scripts/style-curation/category-reviews.json`: `expectedCount` and `baselineHash` (compute them with `auditStyleCuration` from `scripts/audit-style-curation.ts`), and note the change in `proposedAction`. Then `bun run styles:curation:verify`.
7. Update the preset count in `components/recipes/stylePresetManifests.test.ts` (`toHaveLength(...)`) and run `bun run test -- components/recipes/stylePresetManifests.test.ts`.
8. Write `audits/<pack>__<slug>.md` and mark the row in `PLAN.md`. Commit one category per commit.

## Quality bar for briefs (the user's main complaint)

- Creative, specific, memorable: one striking idea, a clear composition (diagonal, scale contrast, worm's-eye view), readable at thumbnail size. Dark medieval fantasy is welcome where it fits; a photography or modifier category still needs subjects that _show off that technique_ (a hard-flash card must visibly show flash).
- The medium and technique are spelled out in the brief (palette, marks, light, lens), in words taken from the preset.
- **Never repeat a subject across presets in a category.** Legacy briefs caused the same bearded man in an olive shirt, the same brunette, trams, cyclists, and wet plazas with umbrellas everywhere. Avoid those tropes.
- Original subjects only. No real people or celebrities, no franchise characters, no readable text, logos or UI. Adults, except where the category needs a child (school portrait, newborn), kept wholesome.
- The 3 briefs of one preset differ in subject, setting and composition.
- Good examples: SP17-096…125 in `scripts/style-curation/card-briefs.json`, and the two specs in `specs/`.

## Quality bar for DNA

Follow `docs/styles/curation-v2/agent-kit/FIELD-RULES.md`. Each field states a concrete mechanism (lens, light ratio, stroke, ink, palette, finish). No template sentences like "acts as a transferable … style router". Modifiers (lighting, materials, film) change only their aspect and keep the prompt's subject and setting. The `creative_brief` field is generated by `apply.ts`.
